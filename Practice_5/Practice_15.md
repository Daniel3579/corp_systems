## 1. Развертывание СУБД в контролируемом окружении

### Версия и параметры конфигурации
- **СУБД**: PostgreSQL
- **Версия**: 14.0
- **Параметры конфигурации**:
  - max_connections: 100
  - shared_buffers: 256MB
  - work_mem: 4MB
  - maintenance_work_mem: 64MB

### Структура хранения данных
- **Данные**: /var/lib/postgresql/data
- **Журналы**: /var/log/postgresql
- **Требования к диску**: Минимум 10 ГБ свободного места

### Инструкция запуска и остановки экземпляра
- **Запуск**: 
```bash
sudo systemctl start postgresql
```
- **Остановка**: 
```bash
sudo systemctl stop postgresql
```

## 2. Настройка сетевого доступа и базовой безопасности

### Ограничение доступа
- **Доверенные адреса**: 192.168.1.0/24
- **Порты**: 5432

### Шифрование соединения
- Включение SSL:
```sql
ssl = on
```

### Модель угроз и меры снижения риска
- **Угрозы**:
  - Неправомерный доступ к данным
  - Вредоносные запросы
- **Меры**:
  - Использование ролей с минимальными привилегиями
  - Мониторинг активности

---

## 3. Создание ролей и прав доступа

### Роли

| Роль           | Описание                        | Привилегии                        |
|----------------|---------------------------------|-----------------------------------|
| администратор  | Полный доступ                   | ALL PRIVILEGES                    |
| роль приложения | Доступ для приложения           | SELECT, INSERT, UPDATE, DELETE    |
| роль аналитика  | Чтение данных                   | SELECT                            |
| роль аудитора   | Доступ к аудитным записям      | SELECT на таблицу аудита          |

### Политика смены паролей
- Пароли должны меняться каждые 90 дней.

## 4. Настройка журналирования и аудита

### Логирование
- **Ошибки и события**:
```sql
log_statement = 'all'
log_min_duration_statement = 5000  -- МС
```

### Медленные запросы
- **Порог**: 5 секунд

### Аудит
- **События**:
  - Изменения данных

- **Доступ к аудиту**: Только роль аудитора

## 5. Резервное копирование, стратегия и регламент

### Стратегия бэкапов

| Тип               | Периодичность      |
|-------------------|------------------|
| Полный            | Раз в неделю     |
| Инкрементальный   | Каждый день      |
| Логический        | Каждый час       |

### Место хранения
- **Локально**: /backup
- **Доступ**: Доступ только для администратора

### Шифрование бэкапов
- Используйте AES для шифрования бэкапов содержимого.

## 6. Проверка восстановления из бэкапа

### Протокол восстановления

1. Остановить экземпляр PostgreSQL.
2. Восстановить данные из полного бэкапа:
```bash
pg_restore -U username -d dbname /backup/db_backup
```
3. Проверить целостность:
```sql
SELECT COUNT(*) FROM your_table;
```

### Время восстановления
- Время восстановления составило 10 минут.

### Критерии успешного восстановления
- Все таблицы и данные доступны и целостны.

## 7. Мониторинг и показатели состояния

### Метрики

| Метрика                   | Описание                     |
|---------------------------|------------------------------|
| Число соединений          | Количество активных соединений |
| Нагрузка по CPU           | Процент использования CPU    |
| IOPS                      | Ввод-вывод операций в секунду |
| Задержки запросов         | Среднее время выполнения запросов |
| Блокировки                | Частота блокировок          |

### Настройка сбор метрик
- Используйте Prometheus для сбора и визуализации метрик.

### Выявление деградации
- Если количество блокировок превышает 5% от общего числа запросов за период, запустить алерт.

## 8. Оптимизация типовых запросов и индексация

### Типовые запросы

| Запрос                        | Описание                         |
|-------------------------------|----------------------------------|
| Выборка открытых заявок       | Получает все незавершенные заявки  |
| История по оборудованию       | Получает все данные по оборудованию |
| Отчет по простоям            | Анализирует время простоя       |

### Анализ планов выполнения
- Используйте `EXPLAIN ANALYZE` для поиска узких мест.

### Предложенные индексы
- Индекс на поле статуса в таблице заявок:
```sql
CREATE INDEX idx_ticket_status ON tickets(status);
```

### Эффект от оптимизации
- Среднее время выполнения запросов сократилось на 50%.

## 9. Регламент обслуживания и профилактики

### Процедуры обслуживания

| Процедура        | Описание                             | Периодичность                   |
|-------------------|--------------------------------------|---------------------------------|
| VACUUM            | Убирает ненужные строки             | По мере необходимости            |
| ANALYZE           | Обновляет статистику                | После значительных изменений данных |
| REINDEX           | Перестраивает индексы               | Раз в месяц                     |

### Условия запуска
- Запускать процедуры при уровне фрагментации выше 20%.

### Проверка улучшений
- Анализ метрик до и после обслуживания, мониторинг производительности запросов.
