## 1. Выбор стандартов и протоколов для взаимодействия компонентов

### Протоколы и стандарты

| Протокол      | Описание                                                  | Переваги                                             |
|---------------|-----------------------------------------------------------|-----------------------------------------------------|
| HTTP          | Протокол передачи данных в сети                           | Широкая поддержка, простой в использовании          |
| HTTPS         | HTTP с шифрованием через TLS                              | Обеспечивает безопасность передачи данных            |
| TLS           | Протокол для обеспечения безопасности соединений          | Шифрование и защита данных от прослушивания         |
| JWT           | JSON Web Tokens для аутентификации                        | Простота использования и безопасность передачи токенов |
| OAuth2        | Протокол авторизации для предоставления доступов          | Гибкость и контроль доступа к ресурсам              |
| OpenAPI       | Стандарт для описания API                                | Упрощает создание документации и тестирования API   |

### Требования к шифрованию и сертификатам
- **Шифрование**: Все соединения должны использовать HTTPS.
- **Сертификаты**: Использовать сертифицированные CA.
- **Минимальные версии**: Поддерживать TLS 1.2 и выше.

## 2. Регламент версионирования API и контрактов

### Правила версионирования

| Тип изменения       | Описание                                    | Версия            |
|---------------------|---------------------------------------------|-------------------|
| Ломающее           | Изменения в структуре данных, удаление эндпоинтов | Увеличение мажорной версии |
| Неломающее         | Добавление новых функциональностей, полей   | Увеличение минорной версии |

### Политика поддержки старых версий
- Поддержка старых версий API в течение 1 года после выхода новой.
- Уведомление пользователей о прекращении поддержки минимально за 3 месяца.

### Обратная совместимость
- Использовать версионирование в URL, например `/api/v1/resource`.
- Обеспечивать возможность использования старых версий без изменений на стороне клиента.

## 3. Правила модификации схемы базы данных

### Процесс миграций

| Этап                | Описание                                    |
|---------------------|---------------------------------------------|
| Разработка миграции | Создание .sql файлов с изменениями схемы    |
| Тестирование        | Протестировать миграцию на тестовой БД     |
| Применение          | Применение миграции в продакшн с использованием инструмента (например, Liquibase) |

### Меры против потери данных
- Создание резервной копии перед каждой миграцией.

### Стратегия отката миграции
- Если возникла ошибка, откатить изменения до состояния до миграции.
- Откат обязателен, если данные стали недоступны или некорректны.

### Управление секретами

|---------------------------|--------------------------------------------|

## 7. Тестирование и критерии качества релиза

### Набор тестов

| Тип тестирования         | Описание                                  |
|--------------------------|-------------------------------------------|
| Модульные                | Проверка отдельных компонентов            |
| Интеграционные           | Проверка взаимодействия компонентов       |
| Контрактные              | Проверка соответствия с OpenAPI          |
| Нагрузочные              | Тестирование под высокой нагрузкой        |

### Критерии для запрещения релиза
- Если доля ошибок превышает 5% или падение ключевых тестов.

### Фиксация результатов тестов
- Все результаты тестов фиксируются в CI/CD, доступные для анализа.

## 8. CI CD и управление выпуском

### Пайплайн

| Этап              | Описание                                  |
|-------------------|-------------------------------------------|
| Сборка            | Компиляция и сборка проекта               |

- Переключение только после подтверждения успешного выполнения на стейджинге.

### Механизм отката
- Откат в случае обнаружения критических ошибок после релиза.
