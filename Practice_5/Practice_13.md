## 1. Определение границ клиент серверного контура

### Операции
1. Создание заявки
2. Изменение статуса заявки
3. Назначение исполнителя
4. Получение списка заявок
5. Получение информации о заявке
6. Удаление заявки

### Роли пользователей
- **Сотрудник**: может создавать, изменять и удалять заявки, назначать исполнителя.
- **Менеджер**: может просматривать, изменять статусы и назначать исполнителей.

### Допущения
- Нет интеграций с внешними системами на первом этапе.
- Все операции выполняются в пределах одной системы.

## 2. Проектирование API и контрактов

### Эндпоинты

| Операция                  | HTTP Метод | Путь                         | Параметры          | Тело запроса                           | Успешный ответ  | Код ошибки      |
|---------------------------|------------|------------------------------|--------------------|----------------------------------------|------------------|-----------------|
| Создание заявки           | POST       | /api/tickets                 | None               | { "title": "string", "description": "string" }  | { "id": int }    | 400, 500        |
| Изменение статуса заявки   | PATCH      | /api/tickets/{id}/status     | id: int            | { "status": "string" }               | { "success": true } | 404, 400        |
| Назначение исполнителя    | PATCH      | /api/tickets/{id}/assignee   | id: int            | { "userId": int }                     | { "success": true } | 404, 400        |
| Получение списка заявок   | GET        | /api/tickets                 | None               | None                                   | [{ "id": int, "title": "string" }] | 500             |
| Получение информации о заявке | GET    | /api/tickets/{id}            | id: int            | None                                   | { "id": int, "title": "string", "status": "string" } | 404              |
| Удаление заявки           | DELETE     | /api/tickets/{id}            | id: int            | None                                   | { "success": true } | 404, 400        |

### Формат ответа
- Успешный ответ:
```json
{
    "success": true,
    "data": { ... }
}
```

- Ошибка:
```json
{
    "success": false,
    "error": {
        "code": int,
        "message": "string"
    }
}
```

Коды ошибок:
- 400: Неверный запрос
- 404: Объект не найден
- 500: Внутренняя ошибка сервера

## 3. Спецификация OpenAPI

```yaml
openapi: 3.0.0
info:
  title: API для управления заявками
  version: 1.0.0
paths:
  /api/tickets:
    post:
      summary: Создание заявки
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                title:
                  type: string
                description:
                  type: string
      responses:
        201:
          description: Заявка создана
          content:
            application/json:
              schema:
                type: object
                properties:
                  id:
                    type: integer
  /api/tickets/{id}:
    get:
      summary: Получение информации о заявке
      parameters:
        - name: id
          in: path
          required: true
          schema:
            type: integer
      responses:
        200:
          description: Успешный ответ
          content:
            application/json:
              schema:
                type: object
                properties:
                  id:
                    type: integer
                  title:
                    type: string
                  status:
                    type: string
```

Правила версионирования:
- Изменения в API не должны ломать существующие версии.

Идемпотентность:
- Методы GET и DELETE должны быть идемпотентными.

## 5. Реализация серверной части

### Стек
- ASP.NET Core

### Структура проекта
- **MySystem.Api** - API
- **MySystem.Core** - Бизнес-логика
- **MySystem.Data** - Доступ к данным

### Обработка ошибок
- Все ошибки обрабатываются в middleware, отвечая стандартным форматом.

### Логирование
- Используем Serilog для логирования.

### Валидация
- Используем FluentValidation для проверки входных данных.

### Конфигурация
- Строки подключения и секреты хранятся в `appsettings.json`.

## 6. Реализация клиента или сценария использования

### Тип клиента
- Консольный клиент

### Пользовательский сценарий
1. Пользователь запускает клиент.
2. Пользователь вводит данные для создания заявки.
3. Клиент отправляет POST запрос к `/api/tickets`.
4. Пользователь видит результат (успех или ошибку).

### Обработка ошибок на стороне клиента
- Ошибки обрабатываются через исключения. Если запрос неуспешен, выводится сообщение об ошибке.

## 9. Тестирование API

### Список тестов
| Название теста                       | Описание                                                            | Ожидаемый результат                    |
|--------------------------------------|---------------------------------------------------------------------|----------------------------------------|
| Тест создания заявки                 | Проверка создания заявки с корректными данными                     | Статус 201, успешный ответ            |
| Тест создания заявки с отсутствующими данными | Проверка создания заявки без необходимых данных                    | Статус 400, ошибка                    |
| Тест изменения статуса заявки        | Проверка изменения статуса существующей заявки                      | Статус 200, успешный ответ            |
| Тест изменения статуса незарегистрированной заявки | Проверка изменения статуса незарегистрированной заявки            | Статус 404, ошибка                    |
| Тест получения списка заявок        | Проверка получения списка заявок                                    | Статус 200, возвращает массив заявок  |
| Тест удаления заявки                 | Проверка удаления существующей заявки                                | Статус 200, успешный ответ            |
| Тест удаления незарегистрированной заявки | Проверка удаления незарегистрированной заявки                        | Статус 404, ошибка                    |
| Тест назначения исполнителя         | Проверка назначения исполнителя на заявку                             | Статус 200, успешный ответ            |
| Тест назначения исполнителя на незарегистрированную заявку | Проверка назначения исполнителя на незарегистрированную заявку   | Статус 404, ошибка                    |
| Тест получения информации о заявке  | Проверка получения информации о существующей заявке                 | Статус 200, успешный ответ            |
| Тест получения информации о незарегистрированной заявке | Проверка получения информации о незарегистрированной заявке      | Статус 404, ошибка                    |
| Тест обработки ошибок                | Проверка корректности обработки ошибок при отправке ошибок          | Статус 500, сообщение об ошибке       |

### Подготовка данных для тестов
- Предварительная настройка тестовой базы данных с фиктивными данными.

### Критерии приемки тестов
- Все тесты должны проходить успешно.
- При наличии критических ошибок релиз запрещен.
